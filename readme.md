# E-Commerce Analytics - Backend

## Overview

This repository contains the backend for an Indian E-Commerce Analytics platform. It provides REST APIs for performing customer, product, and sales analytics and serves the analysis results to the frontend application.

The backend also includes a simple agentic AI layer based on tool calling. The AI agents can interpret analytics-related questions and call the appropriate backend tools to retrieve data and generate responses for customer, product, and sales analysis.

The project follows an ETL-based data pipeline. The raw dataset is extracted from Kaggle, transformed using Python and Pandas, and stored as processed CSV files. Data and pipeline stages are managed using DVC (Data Version Control), allowing changes to datasets and pipeline outputs to be tracked and reproduced.

The current pipeline follows the flow:

**Extract → Transform → Processed Data**

The processed data is currently stored in the processed data directory. Loading the processed data into SQL is planned as the next stage of the pipeline.


## Features

- REST APIs for customer, product, and sales analytics
- Customer, product, and sales KPI analysis
- Data processing and transformation using Python and Pandas
- ETL pipeline for extracting and transforming raw e-commerce data
- Dataset and pipeline versioning using DVC
- AI-powered analytics using tool calling
- Domain-specific AI agents for customer, product, and sales analytics
- OpenAI integration for natural-language analytics queries
- Processed data generation and management
- API-based communication with the frontend

## Architecture

The backend consists of three main layers:

### 1. Data Pipeline

The data pipeline follows an ETL approach:

```text
Kaggle Dataset
      ↓
   Extract
      ↓
 Raw CSV Data
      ↓
  Transform
 (Python + Pandas)
      ↓
Processed CSV Data
      ↓
 DVC Version Control
      ↓
 Planned: Load into SQL
```

DVC is used to track and version the datasets and outputs generated by the data pipeline.

### 2. Analytics API

The processed data is used by the analytics layer to perform customer, product, and sales analysis.

```text
Processed Data
      ↓
Analytics / Business Logic
      ↓
FastAPI REST APIs
      ↓
Frontend Application
```

The APIs expose KPIs and analytical results that are consumed by the frontend dashboard.

### 3. AI Analytics

The backend also contains domain-specific AI agents that use tool calling to answer analytics questions.

```text
User Question
      ↓
AI Agent
      ↓
Identify Required Analytics Tool
      ↓
Call Backend Tool
      ↓
Retrieve / Calculate Data
      ↓
AI Generates Response
      ↓
Frontend
```

The AI layer currently includes separate agents for:

* Customer Analytics
* Product Analytics
* Sales Analytics

The AI agents do not directly perform unrestricted database analysis. Instead, they use predefined analytics tools to retrieve the required information and generate responses based on the returned data.

## AI Analytics

The backend includes a simple AI-powered analytics layer that uses **LLM tool calling** to answer questions about the e-commerce data.

Users can ask analytics questions in natural language, and the AI agent determines which predefined analytics tool is required to retrieve the relevant data. The tool executes the required analysis, and the agent uses the returned result to generate the final response.

### Analytics Domains

The AI layer is organized into domain-specific agents:

* **Customer Analytics** — Customer counts, spending, signups, customer behavior, and related metrics.
* **Product Analytics** — Product sales, units sold, revenue, cost, profit, returns, and product-level analysis.
* **Sales Analytics** — Sales KPIs, trends, profitability, discounts, and related sales analysis.

### Tool Calling Flow

```text
User Question
      ↓
AI Agent
      ↓
Identify Required Tool
      ↓
Call Analytics Tool
      ↓
Retrieve / Calculate Data
      ↓
Tool Result
      ↓
AI Agent
      ↓
Natural Language Response
```

The AI layer is integrated with the FastAPI backend, allowing the frontend application to send analytics questions through API endpoints and receive the generated responses.

## Setup & Installation

### 1. Clone the Repository

```bash
git clone <your-backend-repository-url>
cd indian_ecommerce_analytics_backend
```

### 2. Create a Virtual Environment

```bash
python -m venv venv
```

Activate the virtual environment.

**Windows:**

```bash
venv\Scripts\activate
```

**Linux / macOS:**

```bash
source venv/bin/activate
```

### 3. Install Dependencies

Install the required Python packages:

```bash
pip install -r requirements.txt
```

### 4. Configure Environment Variables

Create a `.env` file in the project root directory:

```env
OPENAI_API_KEY=your_openai_api_key
```

The OpenAI API key is required for the AI analytics endpoints.

### 5. Run the Backend

Start the FastAPI development server using Uvicorn:

```bash
uvicorn main:app --reload
```

The backend will be available at:

```text
http://127.0.0.1:8000
```

### 6. API Documentation

Once the server is running, FastAPI provides interactive API documentation:

```text
http://127.0.0.1:8000/docs
```

ReDoc documentation is available at:

```text
http://127.0.0.1:8000/redoc
```


## Environment Variables

The backend uses environment variables to store sensitive configuration values such as API keys.

Create a `.env` file in the project root:

```env
OPENAI_API_KEY=your_openai_api_key
```

### Environment Variables

| Variable         | Description                                                     | Required |
| ---------------- | --------------------------------------------------------------- | -------- |
| `OPENAI_API_KEY` | API key used by the AI analytics agents for OpenAI tool calling | Yes      |

> **Note:** Never commit the `.env` file or expose your API keys publicly. Add `.env` to `.gitignore`.


## Running the Application

After completing the installation and environment variable setup, start the FastAPI backend using Uvicorn:

```bash
uvicorn main:app --reload
```

The application will start at:

```text
http://127.0.0.1:8000
```

### API Documentation

Once the application is running, the interactive API documentation can be accessed at:

```text
http://127.0.0.1:8000/docs
```

ReDoc documentation:

```text
http://127.0.0.1:8000/redoc
```

The `--reload` option automatically restarts the server when code changes are detected during development.
